# A small pull request workflow

1. Start a branch for one coherent change.
2. Commit the change with a concrete message.
3. Open a pull request that explains the behavior and relevant checks.
4. Run the checks appropriate to the change.
5. Merge using the repository's normal rules.
6. Keep the merge record so the change can be traced later.

For personal practice repositories, an unreviewed documentation merge can be intentional. Shared and production repositories should follow their established review requirements.
